# Storage Schema Overview

This document describes the current schema definitions and data-access code. PostgreSQL has two tables; Milvus collections and Redis structures are grouped separately. `PK` means primary key, including an implicit non-null constraint and unique index. Fields without DEFAULT have no explicitly declared database default.

## Session Messages (PostgreSQL)

### `session_message`

One row per persisted conversation message. Stores session identity, role, content, and creation time, providing history when the Redis cache is empty.

| Field | Type | Constraints | Description |
| --- | --- | --- | --- |
| `message_id` | `UUID` | PK | UUID v4 generated by the application when writing the message |
| `create_at` | `TIMESTAMPTZ` | NOT NULL, DEFAULT `NOW()` | Message creation time; the actual field name is `create_at` |
| `session_id` | `TEXT` | NOT NULL | Session identifier, without a foreign key to a session master table |
| `role` | `TEXT` | NOT NULL | Message role; model comments list system, user, and assistant |
| `content` | `TEXT` | NOT NULL | Message content |

Constraints and indexes:

- `INDEX idx_session_message_session_id (session_id, create_at)` supports history queries by session and time.
- `session_id` has no foreign key; no session master table exists. `role` has no database enum check.
- All messages are written to PostgreSQL first, then Redis. There is no option to disable message persistence.
- On a cache miss, history is loaded in `create_at` order and copied into Redis. No additional ordering field resolves equal timestamps.
- Expiration clears only the message cache and retains persisted history. `delete_session()` deletes the session's PostgreSQL messages and Redis message list.

## Model Service Resources (PostgreSQL)

### `openai_resource`

One row per OpenAI-compatible model service configuration, storing connection settings, enabled status, selection priority, and soft-deletion time.

| Field | Type | Constraints | Description |
| --- | --- | --- | --- |
| `resource_id` | `TEXT` | PK | UUID v4 string generated by the creation method |
| `model` | `TEXT` | NOT NULL | Model name |
| `api_key` | `TEXT` | NOT NULL | API key; the current accessor reads and writes it as text |
| `base_url` | `TEXT` | NOT NULL | OpenAI-compatible service URL |
| `deleted_at` | `TIMESTAMPTZ` | NULL | Soft-deletion time; NULL for records that have not been deleted |
| `enabled` | `BOOLEAN` | NOT NULL, DEFAULT `TRUE` | Whether the resource participates in selection |
| `priority` | `INTEGER` | NOT NULL, DEFAULT `0` | Higher values take precedence |

Constraints and indexes:

- `CHECK (deleted_at IS NULL OR enabled = FALSE)`, named `openai_resource_deleted_disabled`, prevents a soft-deleted resource from being enabled.
- `INDEX idx_openai_resource_enabled (enabled, priority DESC)`.
- Model names and service URLs have no unique constraint. `priority` has no non-negative constraint.
- Selection filters by `enabled = TRUE AND deleted_at IS NULL`, sorts by `priority DESC, resource_id`, and takes the first row.
- Soft deletion sets `deleted_at = COALESCE(deleted_at, NOW())` and `enabled = FALSE`, retaining the record and its original deletion time.

## Vector Storage (Milvus)

### `{collection_name}`

Call `MilvusInstance.create_hybrid_collection(collection_name, dimension)` to create a standalone collection. Each record stores text and its vectors without depending on PostgreSQL business tables. The caller supplies the collection name.

| Field | Type | Constraints | Description |
| --- | --- | --- | --- |
| `kn_id` | `VARCHAR` | PK, max_length=64 | Caller-supplied record ID; the field name is retained for compatibility with existing vector calls |
| `value` | `VARCHAR` | max_length=65535, enable_analyzer=True | Text content and BM25 input |
| `sparse_vector` | `SPARSE_FLOAT_VECTOR` | Generated by the BM25 function | Sparse text vector; not supplied by the caller |
| `embedding` | `FLOAT_VECTOR` | dim=dimension | Dense vector whose dimension must match the collection configuration |

Constraints and indexes:

- `auto_id=False` and `enable_dynamic_field=False`; upsert and delete use `kn_id`.
- `embedding`: `AUTOINDEX` with the `COSINE` metric.
- `sparse_vector`: `SPARSE_INVERTED_INDEX` with the `BM25` metric. The `bm25` function generates sparse vectors from `value`.
- Dense search uses `search(..., vector_field="embedding")`. Hybrid search uses `hybrid_search()` and combines results with WeightedRanker.
- Existing collections are not automatically modified; callers must ensure schema compatibility. The generic `create_collection()` helper remains available but does not create this hybrid-search schema.
- KnowledgeEngine still provides embeddings. Milvus methods can be called independently of sessions or the former knowledge model.

## Session Cache (Redis)

### `session:{session_id}:messages`

One List per session. Each element is a JSON message containing live conversation data or cached persisted history. Types below refer to the application JSON model.

| Field | Type | Constraints | Description |
| --- | --- | --- | --- |
| `role` | `str` | Required by the application model | Message role |
| `content` | `str` | Required by the application model | Message content |

Constraints and indexes:

- Append with `RPUSH` and read with `LRANGE 0 -1`. There are no relational primary keys, foreign keys, or secondary indexes.
- List entries do not include PostgreSQL's `message_id` or `create_at`.
- Writes set no TTL. Session expiration cleanup deletes this key.

`service_structs.py` also declares a `SessionMeta` model for `session:{session_id}:meta`, but no actual read/write implementation was found, so it is not listed as an implemented storage structure. Invocation logs are stored in files. The client has no independent database tables.
